# Workout Plan Generator

A single-page Streamlit app that turns a few structured questions about your
fitness goals into a personalized, weekly workout plan generated by an LLM
via the [Groq API](https://console.groq.com/).

## What it does

You tell the app:
- Your fitness goal (Build muscle / Lose fat / General fitness / Improve endurance)
- Your experience level (Beginner / Intermediate / Advanced)
- How many days a week you can train (1–7)
- What equipment you have access to (No equipment / Home dumbbells / Full gym)
- Optionally, any injuries or limitations (e.g. "bad knees")

...and it returns a day-by-day plan (exercises, sets, reps) that respects
those constraints — not a generic "do some squats" response.

📖 For architecture details, the full error-handling matrix, and a guide to
tweaking the LLM's prompt/schema/model, see
[TECHNICAL_DOCUMENTATION.md](TECHNICAL_DOCUMENTATION.md).

## Project structure

| File | Responsibility |
|---|---|
| `app.py` | Streamlit UI: collects input, shows output, session state, download/regenerate |
| `workout_models.py` | Typed data structures (`WorkoutRequest`, `GenerationResult`) |
| `prompts.py` | System prompt + user prompt builder — the actual prompt design |
| `workout_generator.py` | Input validation + the Groq API call, wrapped in try/except |

## Setup

1. **Clone the repo and create a virtual environment**
   ```bash
   python -m venv venv
   venv\Scripts\activate        # Windows
   # source venv/bin/activate   # macOS/Linux
   ```

2. **Install dependencies**
   ```bash
   pip install -r requirements.txt
   ```

3. **Add your Groq API key**

   Copy `.env.example` to `.env` and fill in your key (get one free at
   https://console.groq.com/keys):
   ```
   GROQ_API_KEY=your_groq_api_key_here
   GROQ_MODEL=openai/gpt-oss-120b   # optional — see "Notes on model choice" below
   ```

4. **Run the app**
   ```bash
   streamlit run app.py
   ```

## Design notes

- **Structured inputs, not free text.** All core inputs are dropdowns/sliders
  (`WorkoutRequest` in `workout_models.py`) and are passed to the prompt as
  explicit labeled fields, not blended into a single sentence.
- **Prompt design.** The system prompt (`prompts.py`) explicitly instructs the
  model to: respect equipment/day/injury constraints exactly, stay out of
  medical-advice territory, and only include a safety disclaimer when
  limitations are actually reported. The user prompt restates the day count
  as a hard numeric requirement, since models otherwise default to a generic
  7-day split.
- **Structured output via JSON schema, not parsed Markdown.** Rather than
  asking the model for Markdown and hoping it stays parseable, the app uses
  Groq's structured-output mode (`response_format: json_schema`, defined in
  `WORKOUT_PLAN_SCHEMA` in `prompts.py`) so the API itself validates the
  model's response against an exact schema before it comes back. This is
  what lets the UI render real per-day expander cards with an exercise table
  (Exercise / Sets / Reps / Notes), a metrics summary bar, and a proper
  warning banner for the disclaimer — instead of one long block of raw text.
- **Error handling.** `validate_request()` catches invalid/missing input
  (e.g. 0 days) before any API call is made. `generate_workout_plan()` wraps
  the Groq call in try/except covering auth errors, rate limits, timeouts,
  connection errors, and generic failures. Groq validates the JSON response
  against the schema server-side and returns a 400 if the model's generation
  doesn't comply (an occasional model glitch, not a code bug) — the app
  treats this, along with an empty/unparseable response, as retryable and
  automatically retries the call once before showing a friendly fallback
  message, so a transient bad generation is invisible to the user.
- **Stretch goals implemented:** last plan persists via `st.session_state`,
  a "Regenerate" button asks for a different variation, and a download
  button exports the plan as `.md`.

## Notes on model choice

Uses Groq's `openai/gpt-oss-120b` model by default (Groq's recommended
replacement after `llama-3.3-70b-versatile` was decommissioned in August
2026). The model is configurable via the `GROQ_MODEL` environment variable
(see `.env.example`) — set it in `.env` to try a different Groq-hosted model
without touching code. Check https://console.groq.com/docs/models for the
current list, since Groq periodically deprecates older models.
